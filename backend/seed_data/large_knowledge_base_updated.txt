# IT Security and Data Privacy Policy
## 1. Access Control
All employees must use multi-factor authentication (MFA) to access company systems. Passwords must be at least 16 characters long and rotated every 90 days. Access to production databases is strictly limited to authorized personnel in the DevOps and Database Administration teams.

## 2. Data Encryption
All customer data must be encrypted at rest using AES-256 and in transit using TLS 1.3 or higher. Passwords must be hashed using bcrypt or Argon2 with a minimum work factor of 12.

## 3. Incident Response
In the event of a suspected security breach, employees must immediately notify the Security Operations Center (SOC) at security@technova.com. The Incident Response Team (IRT) will convene within 15 minutes of a reported severity 1 incident.


# Database Architecture Guidelines
Our platform relies on a distributed PostgreSQL architecture for transactional data and ClickHouse for analytical workloads.

## Transactional Databases (PostgreSQL)
- **Primary-Replica Setup:** All clusters must have at least one primary and two read replicas across different availability zones (AZs).
- **Connection Pooling:** PgBouncer must be used to manage database connections. Applications should never connect directly to PostgreSQL.
- **Migrations:** All schema changes must be managed through Alembic and reviewed by at least one Database Engineer.

## Analytical Databases (ClickHouse)
- Data is synced from PostgreSQL to ClickHouse using Debezium CDC (Change Data Capture) via Kafka.
- Queries on ClickHouse should leverage materialized views for frequently accessed aggregations.


# Employee Handbook & Leave Policy
## Vacation Time (PTO)
Full-time employees accrue 20 days of Paid Time Off (PTO) per year. Up to 5 days of unused PTO can be rolled over to the next calendar year.

## Sick Leave
Employees are entitled to 10 days of paid sick leave annually. For absences exceeding 3 consecutive days, a doctor's note may be required.

## Remote Work
TechNova is a remote-first company. Employees may work from anywhere, provided they maintain at least 4 hours of overlap with the core business hours (9 AM - 5 PM EST) for team collaboration.


# Software Development Life Cycle (SDLC)
## Version Control
We use Git for version control. All code must be hosted on our internal GitLab instance.
- `main` branch: Always deployable to production.
- `staging` branch: Used for pre-production testing.
- Feature branches: Created from `main`, must follow the naming convention `feature/JIRA-TICKET-description`.

## CI/CD Pipeline
Every merge request (MR) triggers an automated pipeline that runs:
1. Linting (Ruff for Python, ESLint for JS).
2. Unit tests (pytest for Python, Jest for JS).
